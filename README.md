# Secure Subscription Collector

Автоматический сборщик профилей для Android-клиентов, совместимых с URI-форматами **VLESS**, **Trojan** и **Hysteria2**. Проект получает HTTPS-подписки из `input.txt` только для обнаружения публичных Telegram-каналов в разрешённых URI. В `output/` публикуются исключительно профили, извлечённые из публичных Telegram-preview, прошедшие статический фильтр и IP-проверку через Xray; прямые профили из подписок не публикуются.

> Для каждого профиля сборщик создаёт временную Xray-конфигурацию с SOCKS-входом только на `127.0.0.1`, проверяет JSON командой `xray run -test`, запускает ядро и выполняет запросы через этот локальный прокси. Сначала проверяются независимые сервисы публичного IP; если они не подтвердили профиль, выполняется резервная HTTPS-проверка доступности. В итоговый файл попадает только профиль с успешным ответом через собственный Xray outbound. Процесс Xray и временный JSON удаляются после каждой попытки, в том числе при ошибке или тайм-ауте.

## Поддерживаемые протоколы

| Протокол | Требования статического фильтра |
|---|---|
| VLESS | UUID; TLS с SNI и fingerprint либо Reality с `encryption=none`, SNI, fingerprint и `pbk` |
| Trojan | Пароль, TLS, SNI и fingerprint |
| Hysteria2 / `hy2` | Пароль, TLS и SNI |

Все остальные схемы исключаются. Профили с `allowInsecure=1` или `insecure=1` не публикуются.

## Накопительные файлы по протоколам

При успешной публикации команда автоматически создаёт каталог `output/`, если его ещё нет. В нём поддерживаются три файла с URI соответствующего протокола.

| Протокол | Файл |
|---|---|
| VLESS | `output/vless.txt` |
| Trojan | `output/trojan.txt` |
| Hysteria2, включая `hy2` | `output/hysteria2.txt` |

При каждом запуске сборщик атомарно заменяет каждый файл набором профилей соответствующего протокола, извлечённых из публичных Telegram-preview и прошедших текущую Xray IP-проверку. Поэтому ранее опубликенный, но больше не проверенный профиль не остаётся в конечном файле, а остановка процесса не оставляет частично записанный файл. Пустые файлы для протоколов без успешно проверенных профилей также создаются при первой публикации.

Каждый профиль сохраняется в совместимом URI-формате, а его имя после `#` заменяется коротким ASCII-фрагментом:

```text
TYPE-SECURITY-TRANSPORT-CODE
```

Примеры:

```text
VL-REALITY-GRPC-3ScvEG
TR-TLS-TCP-3ScvEG
HY2-TLS-UDP-3ScvEG
```

`CODE` — стабильный шестизначный буквенно-цифровой идентификатор. В имени нет IP/домена, SNI, UUID, пароля, ключа или исходного названия из сторонней подписки. Используются только буквы, цифры и дефисы, поэтому Android-клиенты отображают имя без URL-кодирования `%20` и специальных символов.

## Дедупликация

Дубликаты с одинаковыми параметрами подключения удаляются независимо от порядка query-параметров или исходного имени. Эта проверка применяется как к профилям одного запуска, так и к повторному добавлению в уже существующие файлы `output/`.

Профили с одинаковыми сервером и портом, но разными SNI, Reality-ключами, TLS-параметрами, транспортом или другими соединительно значимыми полями сохраняются как отдельные конфигурации. Такое поведение соответствует ожиданиям Android-клиентов наподобие v2rayNG и NekoBox.

## Настройка и запуск

Все постоянные параметры находятся в едином файле [`config.yaml`](config.yaml). Каждый параметр сопровождается русскоязычным комментарием: пути к входным и выходным файлам, лимиты загрузки источников, параллельность статического фильтра, полный набор лимитов Xray IP-проверки, политика публикации и версия Xray для GitHub Actions. Не изменяйте значения в исходных файлах Python или workflow.

Укажите в `input.txt` публичные HTTPS-адреса подписок, по одному на строку. Профили в этих документах используются для обнаружения публичных Telegram-каналов и не записываются в `output/` напрямую. Для локального запуска укажите в `config.yaml` путь к установленному бинарнику Xray в `paths.xray_path`, затем выполните:

```bash
python -m subscription_collector
```

Используйте другой файл настроек через `--config`:

```bash
python -m subscription_collector --config /path/to/config.yaml
```

Параметры командной строки остаются только временным переопределением значений из YAML, например для пути к скачанному Xray в CI:

```bash
python -m subscription_collector --xray-path /path/to/xray
```

Флаги `--strict-first-seen` и `--no-strict-first-seen`, а также `--fail-on-empty` и `--no-fail-on-empty`, временно переопределяют одноимённые логические параметры раздела `behavior`. Параметр `strict_first_seen` ограничивает публикацию текущих кандидатов профилями, впервые замеченными в окне `sources.max_age_hours`. Параметр `fail_on_empty` возвращает код `2`, если текущий запуск не опубликовал ни одного профиля; файлы при этом содержат только текущий пустой набор, а не исторические результаты.

## Журнал выполнения и отчёт

Команда выводит русскоязычный журнал в стандартный вывод. Этапы охватывают подготовку, загрузку источников, статическую фильтрацию, удаление повторов, Xray IP-проверку и публикацию. Информационные сообщения `httpx` и `httpcore`, а также построчные данные об URI подавляются.

В журнал и `report.json` не попадают URI, домены, IP-адреса, SNI, ключи, учётные данные, исходные имена или содержимое ответов источников. После Xray-этапа журнал выводит только обезличенную сводку категорий отказов, например `ip_timeout: 42`; она помогает отличить проблему контрольных URL от ошибочной конфигурации профилей. В отчёте сохраняются только агрегированные причины исключения, свежесть источников, длительности этапов и безопасные количества новых и итоговых профилей по протоколам.

## Файлы проекта

| Файл или каталог | Назначение |
|---|---|
| `config.yaml` | Единая постоянная конфигурация с русскоязычными пояснениями всех параметров |
| `input.txt` | Публичные HTTPS URL подписок: один адрес на строку |
| `output/` | Накопительные файлы `vless.txt`, `trojan.txt` и `hysteria2.txt` |
| `report.json` | Обезличенные итоги обработки и публикации |
| `.collector/state.json` | Отпечатки профилей и даты первого/последнего наблюдения без секретов |

## Автоматическое обновление

Обновление запускается вручную или по расписанию — каждые четыре часа. Workflow устанавливает Python-зависимости, читает версию Xray из `config.yaml`, скачивает официальный архив Xray для Linux x64, сверяет его SHA-512 с опубликованным файлом `.dgst`, а затем передаёт только временный путь к бинарнику сборщику. Xray используется только во время задания и не коммитится; публикуются только изменившиеся `output/`, `report.json` и `.collector/state.json`.

Изменение кода не запускает сбор подписок. Лимиты параллельности, размеры групп, тайм-ауты, наборы IP-echo и HTTPS-проверок, допустимые HTTP-коды и политика публикации в текущем workflow читаются из `config.yaml`. После дедупликации все поддерживаемые профили проверяются только через Xray; профиль исключается, только если ни один настроенный IP-echo и резервный HTTPS-сервис не подтвердили соединение через его локальный SOCKS-вход.

## Ограничения

Возраст отдельного URI невозможно достоверно установить, если источник не передаёт дату публикации; при наличии HTTP `Last-Modified` применяется окно `sources.max_age_hours` из `config.yaml`. Успешная IP-проверка подтверждает работоспособность конкретного профиля из сети GitHub Actions на момент запуска, но не гарантирует доступность из сети пользователя или в будущем. Импорт и использование опубликованных профилей остаются под контролем пользователя.

## Публичные Telegram-каналы

Помимо HTTPS-подписок сборщик обнаруживает публичные Telegram-каналы в URI разрешённых схем VLESS, Trojan, `hy2` и `hysteria2`. Поддерживаются canonical username в формах `@channel`, `t.me/channel`, `t.me/s/channel`, `telegram.me/channel` и `tg://resolve?domain=channel`, включая безопасно URL-кодированные и HTML-экранированные значения. Private-invite, `joinchat`, `t.me/c/...`, страницы без публичного username и любые сценарии, которые требуют входа, не запрашиваются.

Для каждого канала сборщик читает только публичный preview `https://t.me/s/<handle>`. Он обходит страницы через публичный параметр `before` до тех пор, пока не достигнет надёжно датированных постов старше **24 часов**, не увидит повторный курсор или не получит страницу без новых сообщений. Число извлечённых постов и профилей не ограничивается; ограничены только параллелизм, время запроса, размер HTML-ответа и число HTTPS-перенаправлений из `config.yaml`. В отличие от источников подписок, для которых заголовок `Last-Modified` допускает возраст до **72** часов, Telegram-пост без надёжной даты не считается новым.

Найденный Telegram-профиль проходит тот же обязательный путь, что и прямой профиль из подписки: строгий статический фильтр, глобальную дедупликацию и Xray IP-проверку. Отдельного ослабленного пути публикации нет. Поэтому прошедшие Telegram-профили записываются в обычные файлы соответствующих протоколов в `output/`.

### Адаптивная оценка каналов

Система сохраняет только обезличенные агрегаты канала: активность, долю поддерживаемых и статически безопасных URI, уникальность, повторяемость и сглаженный результат Xray. На их основе канал получает один из статусов `candidate`, `watch`, `approved` или `excluded`. Новый канал должен накопить доказательства; по мере появления независимых наблюдений его порог плавно приближается к базовому. Успешные Xray-проверки повышают оценку, серия отказов её снижает, а временная недоступность preview не обнуляет уже подтверждённый результат. Канал может вернуться из `excluded` или `watch` в `approved` после устойчивого улучшения.

| Файл | Назначение |
|---|---|
| `tg_channels.txt` | Атомарно обновляемый отсортированный список `@handle` качественных публичных каналов со статусом `approved` и недавним успешным Xray-результатом. |
| `.collector/channel_state.json` | Обезличенное адаптивное состояние с хешированными ключами каналов; URI, текст постов, домены, ключи и учётные данные не сохраняются. |
| `.collector/tg_registry.txt` | Служебный список обнаруженных публичных каналов для повторной оценки. |
| `report.json` | Только суммарные количества Telegram-каналов, постов и статусов без содержимого источников. |

Все Telegram-ограничения, сетевые параметры и коэффициенты оценки находятся в разделе `telegram` файла `config.yaml`.
