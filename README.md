# Secure Subscription Collector

Сборщик безопасных подписок для Android-клиентов: получает профили **VLESS / Trojan / Hysteria2** из HTTPS-подписок и публичных Telegram-каналов, проверяет их и публикует готовые файлы.

## Конвейер

1. Загрузка источников из `input.txt` (окно свежести 72 ч).
2. Обнаружение Telegram-каналов и сбор публичных превью `t.me/s/<канал>` за последние **72** часа.
3. Строгая безопасность + глубокий анализ каждого профиля.
4. Дедупликация по правилам v2rayNG.
5. TCP/TLS-проверка серверов (до 300 мс).
6. Публикация в `output/` и отчёта `report.json`.

## Профили

| Протокол | Файл | Требования |
|---|---|---|
| VLESS | `output/vless.txt` | UUID; TLS (SNI + `fp`) или Reality (`pbk`, SNI, `fp`, `encryption=none`) |
| Trojan | `output/trojan.txt` | Пароль, TLS, SNI, `fp` |
| Hysteria2 | `output/hysteria2.txt` | Пароль, TLS, SNI |

- **Глубокий анализ:** известные отпечатки `fp`, допустимые `alpn`, пути WebSocket, режимы gRPC/XHTTP, параметры Reality и obfs Hysteria2, `flow=xtls-rprx-vision` только с TCP.
- **Имена:** `TYPE-SECURITY-TRANSPORT-CODE` — без IP, SNI, ключей и не-ASCII символов.
- **Дубликаты:** идентичность = эффективная исходящая конфигурация, как в v2rayNG: алиасы `ws`≡`websocket`, `tcp`≡`raw`, порядок параметров и мусор поставщика не важны.

## Доступность серверов

Каждый уникальный адрес проверяется параллельно: батчи по 256 конечных точек при 56 воркерах (допустимо 50–60).

- TCP + TLS-рукопожатие не дольше `reachability.timeout_ms` — по умолчанию **300 мс**;
- подтверждение живости: Cloudflare trace `/cdn-cgi/trace`, затем `generate_204`;
- домен без ответа системного DNS — запасной запрос к Google DNS-over-HTTPS (`dns.google/resolve`);
- неответившие профили отбрасываются (`unreachable_endpoint`); Hysteria2 (QUIC/UDP) от TCP-пробы освобождён.

## Telegram-каналы

- Каналы извлекаются из фрагментов `#@name`, ссылок `t.me/...` и `tg://resolve?domain=...`; профили-указатели не публикуются.
- От одного канала — до 1000 профилей за окно.
- **Качество:** адаптивная модель по метрикам активности, доли поддерживаемых URI, статического фильтра, глубины анализа, уникальности и каденса. Порог 45 с надбавками; ускоренное одобрение сильного первого наблюдения; скидка за накопленные наблюдения; учёт момента роста; относительный порог по медиане пула каналов.
- **Статусы:** `candidate` → `approved` / `watch` / `excluded`; в `output/tg_channels.txt` попадают только `approved`, новые каналы добавляются в файл автоматически.
- **Переоценка:** старые каналы из реестра проверяются каждые `telegram.reevaluation_interval` запусков (по умолчанию 3) даже без упоминания в подписках; каналы, переставшие отвечать метрикам, удаляются из реестра и файла.
- **Приватность:** в состоянии каналов имена заменены SHA-256-хешами.

## Запуск

```bash
python -m subscription_collector                 # настройки из config.yaml
python -m subscription_collector --config path/to/config.yaml
```

Все параметры с русскими комментариями — в [config.yaml](config.yaml); флаги CLI лишь временно переопределяют YAML (`--strict-first-seen`, `--fail-on-empty`, лимиты источников, фильтра и проверки доступности).

## Файлы

| Путь | Назначение |
|---|---|
| `config.yaml` | все настройки конвейера |
| `input.txt` | HTTPS-адреса подписок |
| `output/` | `vless.txt`, `trojan.txt`, `hysteria2.txt`, `tg_channels.txt` |
| `report.json` | обезличенный отчёт запуска |
| `.collector/state.json` | отпечатки профилей и даты наблюдений |
| `.collector/channel_state.json` | состояние качества каналов (хеши) |
| `.collector/tg_registry.txt` | реестр известных каналов |

## CI

Workflow каждые 4 часа запускает сборщик и коммитит изменившиеся `output/`, `report.json` и файлы `.collector/`. Ручной запуск — `workflow_dispatch`.

## Ограничения

Возраст URI достоверен только при наличии даты публикации (`Last-Modified` или время Telegram-поста). Статические проверки и TCP/TLS-проба подтверждают корректность и доступность сервера, но не качество прокси-сервиса — итоговая проверка остаётся за пользователем в Android-клиенте.
