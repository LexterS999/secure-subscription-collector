# Secure Subscription Collector

Автоматический сборщик подписок для Android-клиентов, совместимых с URI-форматами **VLESS**, **Trojan** и **Hysteria2**. Проект получает подписки из `input.txt`, исключает неподдерживаемые, неполные и явно небезопасные профили, удаляет дубликаты и публикует только конфигурации, прошедшие статический фильтр и IP-проверку через Xray.

> Для каждого профиля сборщик создаёт временную Xray-конфигурацию с SOCKS-входом только на `127.0.0.1`, проверяет JSON командой `xray run -test`, запускает ядро и запрашивает публичный IP через этот локальный прокси. В итоговый файл попадает профиль только при HTTP `200` и корректном глобальном IP-адресе. Процесс Xray и конфигурационный файл удаляются после каждой попытки, в том числе при ошибке или тайм-ауте.

## Поддерживаемые протоколы

| Протокол | Требования статического фильтра |
|---|---|
| VLESS | UUID; TLS с SNI и fingerprint либо Reality с `encryption=none`, SNI, fingerprint и `pbk` |
| Trojan | Пароль, TLS, SNI и fingerprint |
| Hysteria2 / `hy2` | Пароль, TLS и SNI |

Все остальные схемы исключаются. Профили с `allowInsecure=1` или `insecure=1` не публикуются.

## Накопительные файлы по протоколам

При успешной публикации команда автоматически создаёт каталог `output/`, если его ещё нет. В нём поддерживаются три файла с URI соответствующего протокола.

| Протокол | Файл |
|---|---|
| VLESS | `output/vless.txt` |
| Trojan | `output/trojan.txt` |
| Hysteria2, включая `hy2` | `output/hysteria2.txt` |

При каждом запуске сборщик атомарно заменяет каждый файл набором профилей соответствующего протокола, которые прошли текущую Xray IP-проверку. Поэтому ранее опубликенный, но больше не проверенный профиль не остаётся в конечном файле, а остановка процесса не оставляет частично записанный файл. Пустые файлы для протоколов без успешно проверенных профилей также создаются при первой публикации.

Каждый профиль сохраняется в совместимом URI-формате, а его имя после `#` заменяется коротким ASCII-фрагментом:

```text
TYPE-SECURITY-TRANSPORT-CODE
```

Примеры:

```text
VL-REALITY-GRPC-3ScvEG
TR-TLS-TCP-3ScvEG
HY2-TLS-UDP-3ScvEG
```

`CODE` — стабильный шестизначный буквенно-цифровой идентификатор. В имени нет IP/домена, SNI, UUID, пароля, ключа или исходного названия из сторонней подписки. Используются только буквы, цифры и дефисы, поэтому Android-клиенты отображают имя без URL-кодирования `%20` и специальных символов.

## Дедупликация

Дубликаты с одинаковыми параметрами подключения удаляются независимо от порядка query-параметров или исходного имени. Эта проверка применяется как к профилям одного запуска, так и к повторному добавлению в уже существующие файлы `output/`.

Профили с одинаковыми сервером и портом, но разными SNI, Reality-ключами, TLS-параметрами, транспортом или другими соединительно значимыми полями сохраняются как отдельные конфигурации. Такое поведение соответствует ожиданиям Android-клиентов наподобие v2rayNG и NekoBox.

## Запуск

Укажите в `input.txt` публичные HTTPS-адреса подписок, по одному на строку. Команда запуска с настройками по умолчанию:

```bash
python -m subscription_collector --xray-path /path/to/xray
```

Для явного указания путей:

```bash
python -m subscription_collector \
  --input input.txt \
  --output-dir output \
  --report report.json \
  --state .collector/state.json \
  --xray-path /path/to/xray
```

Параметр `--strict-first-seen` ограничивает публикацию текущих кандидатов профилями, впервые замеченными в окне `--max-age-hours`. Параметр `--fail-on-empty` возвращает код `2`, если текущий запуск не опубликовал ни одного профиля; файлы при этом содержат только текущий пустой набор, а не исторические результаты.

## Журнал выполнения и отчёт

Команда выводит русскоязычный журнал в стандартный вывод. Этапы охватывают подготовку, загрузку источников, статическую фильтрацию, удаление повторов, Xray IP-проверку и публикацию. Информационные сообщения `httpx` и `httpcore`, а также построчные данные об URI подавляются.

В журнал и `report.json` не попадают URI, домены, IP-адреса, SNI, ключи, учётные данные, исходные имена или содержимое ответов источников. В отчёте сохраняются только агрегированные причины исключения, свежесть источников, длительности этапов и безопасные количества новых и итоговых профилей по протоколам.

## Файлы проекта

| Файл или каталог | Назначение |
|---|---|
| `input.txt` | Публичные HTTPS URL подписок: один адрес на строку |
| `output/` | Накопительные файлы `vless.txt`, `trojan.txt` и `hysteria2.txt` |
| `report.json` | Обезличенные итоги обработки и публикации |
| `.collector/state.json` | Отпечатки профилей и даты первого/последнего наблюдения без секретов |

## Автоматическое обновление

Обновление запускается вручную или по расписанию — каждые четыре часа. Workflow устанавливает Python-зависимости, скачивает закреплённый официальный архив Xray для Linux x64, сверяет его SHA-512 с опубликованным файлом `.dgst`, а затем передаёт временный бинарник сборщику. Xray используется только во время задания и не коммитится; публикуются только изменившиеся `output/`, `report.json` и `.collector/state.json`.

Изменение кода не запускает сбор подписок. По расписанию до 32 источников загружаются одновременно, статическая фильтрация работает пулом из 120 потоков батчами по 1024 строки. Перед Xray VLESS и Trojan проходят короткий TCP-предфильтр с параллельностью до 256; Hysteria2/QUIC намеренно его пропускает. Затем одновременно работают до двух временных Xray-процессов, каждый обслуживает батч до 256 профилей через выделенные loopback SOCKS-порты и точную маршрутизацию `localPort` в соответствующий outbound. Внутри каждого батча выполняется до 32 одноразовых IP-запросов без повторов и fallback; профиль сразу исключается при сетевой ошибке, отсутствии валидного IP-ответа или истечении короткого защитного окна в 0,75 секунды.

## Ограничения

Возраст отдельного URI невозможно достоверно установить, если источник не передаёт дату публикации; при наличии HTTP `Last-Modified` применяется окно свежести 72 часа. Успешная IP-проверка подтверждает работоспособность конкретного профиля из сети GitHub Actions на момент запуска, но не гарантирует доступность из сети пользователя или в будущем. Импорт и использование опубликованных профилей остаются под контролем пользователя.
