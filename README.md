# Secure Subscription Collector

Автоматический сборщик подписок для Android-клиентов, совместимых с URI-форматами **VLESS**, **Trojan**, **Hysteria2** и **TUIC v5**. Проект получает подписки из `input.txt`, исключает неподдерживаемые, неполные и явно небезопасные профили, удаляет дубликаты и сохраняет статически допустимые конфигурации в отдельные накопительные файлы по протоколам.

> Сборщик **не** проверяет TCP/TLS-доступность профилей через `sing-box`, Xray, временные прокси-маршруты или URL-кворум. Проверку фактической работоспособности соединения выполняет Android-клиент при импорте или использовании профиля.

## Поддерживаемые протоколы

| Протокол | Требования статического фильтра |
|---|---|
| VLESS | UUID; TLS с SNI и fingerprint либо Reality с `encryption=none`, SNI, fingerprint и `pbk` |
| Trojan | Пароль, TLS, SNI и fingerprint |
| Hysteria2 / `hy2` | Пароль, TLS и SNI |
| TUIC v5 | UUID, пароль, TLS, SNI и версия `5` |

Все остальные схемы исключаются. Профили с `allowInsecure=1` или `insecure=1` не публикуются.

## Накопительные файлы по протоколам

При успешной публикации команда автоматически создаёт каталог `output/`, если его ещё нет. В нём поддерживаются четыре файла с URI соответствующего протокола.

| Протокол | Файл |
|---|---|
| VLESS | `output/vless.txt` |
| Trojan | `output/trojan.txt` |
| Hysteria2, включая `hy2` | `output/hysteria2.txt` |
| TUIC v5 | `output/tuic.txt` |

Файлы не очищаются при следующем запуске. Для каждого из них сборщик читает сохранённые допустимые URI, объединяет их с новыми профилями текущего запуска и записывает итоговый набор атомарно. Благодаря этому уже опубликенные профили сохраняются, а остановка процесса не оставляет частично записанный файл. Пустые файлы для протоколов, которые пока не встретились, также создаются при первой успешной публикации.

Каждый профиль сохраняется в совместимом URI-формате, а его имя после `#` заменяется коротким ASCII-фрагментом:

```text
TYPE-SECURITY-TRANSPORT-CODE
```

Примеры:

```text
VL-REALITY-GRPC-3ScvEG
TR-TLS-TCP-3ScvEG
HY2-TLS-UDP-3ScvEG
TUIC-TLS-UDP-3ScvEG
```

`CODE` — стабильный шестизначный буквенно-цифровой идентификатор. В имени нет IP/домена, SNI, UUID, пароля, ключа или исходного названия из сторонней подписки. Используются только буквы, цифры и дефисы, поэтому Android-клиенты отображают имя без URL-кодирования `%20` и специальных символов.

## Дедупликация

Дубликаты с одинаковыми параметрами подключения удаляются независимо от порядка query-параметров или исходного имени. Эта проверка применяется как к профилям одного запуска, так и к повторному добавлению в уже существующие файлы `output/`.

Профили с одинаковыми сервером и портом, но разными SNI, Reality-ключами, TLS-параметрами, транспортом или другими соединительно значимыми полями сохраняются как отдельные конфигурации. Такое поведение соответствует ожиданиям Android-клиентов наподобие v2rayNG и NekoBox.

## Запуск

Укажите в `input.txt` публичные HTTPS-адреса подписок, по одному на строку. Команда запуска с настройками по умолчанию:

```bash
python -m subscription_collector
```

Для явного указания путей:

```bash
python -m subscription_collector \
  --input input.txt \
  --output-dir output \
  --report report.json \
  --state .collector/state.json
```

Параметр `--strict-first-seen` ограничивает добавление текущих кандидатов профилями, впервые замеченными в окне `--max-age-hours`. Он не удаляет записи, которые уже опубликованы в `output/`. Параметр `--fail-on-empty` возвращает код `2`, если текущий запуск не добавил ни одного нового профиля; сохранённые файлы при этом не меняются.

## Журнал выполнения и отчёт

Команда выводит русскоязычный журнал в стандартный вывод. Этапы охватывают подготовку, загрузку источников, статическую фильтрацию, удаление повторов и публикацию. Информационные сообщения `httpx` и `httpcore`, а также построчные данные об URI подавляются.

В журнал и `report.json` не попадают URI, домены, IP-адреса, SNI, ключи, учётные данные, исходные имена или содержимое ответов источников. В отчёте сохраняются только агрегированные причины исключения, свежесть источников, длительности этапов и безопасные количества новых и итоговых профилей по протоколам.

## Файлы проекта

| Файл или каталог | Назначение |
|---|---|
| `input.txt` | Публичные HTTPS URL подписок: один адрес на строку |
| `output/` | Накопительные файлы `vless.txt`, `trojan.txt`, `hysteria2.txt` и `tuic.txt` |
| `report.json` | Обезличенные итоги обработки и публикации |
| `.collector/state.json` | Отпечатки профилей и даты первого/последнего наблюдения без секретов |

## Автоматическое обновление

Обновление запускается вручную или по расписанию — каждые четыре часа. Workflow устанавливает Python-зависимости, выполняет загрузку источников и статическую фильтрацию, а затем коммитит только изменившиеся `output/`, `report.json` и `.collector/state.json`. Внешние бинарники проверки профилей не загружаются и не запускаются.

Изменение кода не запускает сбор подписок. По расписанию до 32 источников загружаются одновременно, а статическая фильтрация работает пулом из 32 потоков батчами по 1024 строки.

## Ограничения

Возраст отдельного URI невозможно достоверно установить, если источник не передаёт дату публикации; при наличии HTTP `Last-Modified` применяется окно свежести 72 часа. Статическая допустимость URI не гарантирует доступность конкретного сервера или успешность соединения из сети пользователя. Импорт и использование опубликованных профилей остаются под контролем пользователя.
