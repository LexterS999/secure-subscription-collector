# Secure Subscription Collector

Сборщик безопасных подписок для Android-клиентов: получает профили **VLESS / Trojan / Hysteria2** из HTTPS-подписок и публичных Telegram-каналов, проверяет их и публикует готовые файлы.

## Конвейер

1. Загрузка источников из `input.txt` (окно свежести 72 ч).
2. Обнаружение Telegram-каналов и сбор публичных превью `t.me/s/<канал>` за последние **72** часа.
3. Строгая безопасность + глубокий анализ каждого профиля.
4. Дедупликация по правилам v2rayNG.
5. Глубокая TCP/TLS-проверка серверов: несколько попыток на конечную точку, агрегация задержек, грейды и TLS-метаданные.
6. Глубокий замер скорости: прогрев против медленного старта TCP, оконный анализ (среднее/пик/джиттер/стабильность), итоговый скор 0–100 с грейдами A–D.
7. Накопительная публикация в `output/` и отчёт `report.json`.

### Гарантии сетевого слоя

- Каждый документ (источник или страница превью) имеет **жёсткий общий дедлайн** (`total_deadline_seconds`), включающий перенаправления и повторы: медленный сервер не может задержать этап на неопределённое время.
- Временные сбои (сеть, `429/5xx`) повторяются с экспоненциальным backoff и уважением `Retry-After`; детерминированные отказы безопасности — нет.
- Пагинация канала ограничена `max_pages_per_channel` (**50** по умолчанию), что покрывает лимит 1000 профилей за окно.
- Долгие этапы печатают прогресс каждые N завершённых документов/страниц и предупреждают, если этап длится дольше двух минут.

## Профили

| Протокол | Файл | Требования |
|---|---|---|
| VLESS | `output/vless.txt` | UUID; TLS (SNI + `fp`) или Reality (`pbk`, SNI, `fp`, `encryption=none`) |
| Trojan | `output/trojan.txt` | Пароль, TLS, SNI, `fp` |
| Hysteria2 | `output/hysteria2.txt` | Пароль, TLS, SNI |

- **Глубокий анализ:** известные отпечатки `fp`, допустимые `alpn`, пути WebSocket, режимы gRPC/XHTTP, параметры Reality и obfs Hysteria2, `flow=xtls-rprx-vision` только с TCP.
- **Имена:** `TYPE-SECURITY-TRANSPORT-CODE` — без IP, SNI, ключей и не-ASCII символов.
- **Дубликаты:** идентичность = эффективная исходящая конфигурация, как в v2rayNG: алиасы `ws`≡`websocket`, `tcp`≡`raw`, порядок параметров и мусор поставщика не важны.

## Накопление профилей и недельный цикл

Конечные файлы **дополняются** между запусками, а не заменяются профилями текущего запуска:

- каждый профиль хранится в пуле `.collector/profile_pool.json` по стабильному отпечатку вместе с датами добавления;
- повторное появление профиля обновляет дату последнего sightings, а не создаёт дубликат;
- пул ограничен `publication.max_profiles_per_protocol` (**10000** на протокол); при превышении вытесняются самые старые по последнему появлению записи;
- накопление идёт `publication.cycle_days` (**6**) дней; в первый запуск седьмого дня пул сбрасывается до нуля и начинается новый цикл;
- состояние пула коммитится воркфлоу вместе с выходными файлами, поэтому цикл переживает перезапуски CI.

## Проверка доступности (TCP/TLS)

Каждая уникальная конечная точка проверяется `reachability.attempts` (**3**) раза с паузой `retry_delay_ms`: одиночная потеря пакета больше не отбрасывает живой сервер.

- Результаты агрегируются: медианная задержка рукопожатия, число успешных попыток, вердикт «стабильная» (ответили все попытки).
- Задержка получает грейд: `excellent` ≤ `grade_excellent_ms`, `good` ≤ `grade_good_ms`, иначе `fair`.
- Живость подтверждается на прикладном уровне: Cloudflare `/cdn-cgi/trace`, затем Google `/generate_204`, затем голый TCP.
- Для TLS-рукопожатий записываются версия протокола и шифр; путь разрешения DNS (`system`/DoH) попадает в отчёт.
- Отчёт содержит p50/p95 задержек, долю стабильных эндпоинтов и гистограмму грейдов.
- Hysteria2 исключена: протокол работает поверх QUIC/UDP, и TCP-рукопожатие не может доказать или опровергнуть её доступность.

## Проверка скорости

Каждый уникальный профиль пропускает через собственный туннель загрузку файла `speed_test.download_url` и замеряет фактическую скорость.

- Порог записи — `speed_test.min_kbps`, по умолчанию **200 КБ/с**; объём и окно измерения настраиваются.
- Прогрев `warmup_seconds` поглощает медленный старт TCP, чтобы он не занижал первое окно измерения.
- Замер делится на `windows` (**4**) равных окна: считаются средняя и пиковая скорость, джиттер и стабильность (худшее окно к средней).
- Итоговый скор 0–100 = 60% скорость (нормировка на `target_kbps`) + 25% стабильность + 15% задержка из этапа доступности; грейды A ≥ 80, B ≥ 60, C ≥ 40.
- Причины отказа гранулярны: `dns_error`, `connection_refused`, `tls_error`, `handshake_rejected`, `tunnel_timeout`, `upstream_status`, `slow_endpoint`, `insufficient_data`, `unstable_endpoint`.
- Встроенные мини-клиенты на stdlib покрывают **VLESS** (TCP/WS, TLS) и **Trojan** (TCP, TLS).
- Комбинации, требующие отдельного ядра (Hysteria2/QUIC, VLESS Reality и gRPC), скорость измерить нельзя: режим `best_effort` оставляет их после TCP/TLS-пробы, `strict` — отбрасывает (`speed_unmeasured`).
- Параллельность: батчи по `batch_size` при 50–60 воркерах; непрошедшие получают причины `slow_endpoint`, `insufficient_data`, `tunnel_error`.

## Доступность серверов

Каждый уникальный адрес проверяется параллельно: батчи по 256 конечных точек при 56 воркерах (допустимо 50–60).

- TCP + TLS-рукопожатие не дольше `reachability.timeout_ms` — по умолчанию **300 мс**;
- подтверждение живости: Cloudflare trace `/cdn-cgi/trace`, затем `generate_204`;
- домен без ответа системного DNS — запасной запрос к Google DNS-over-HTTPS (`dns.google/resolve`);
- неответившие профили отбрасываются (`unreachable_endpoint`); Hysteria2 (QUIC/UDP) от TCP-пробы освобождён.

## Telegram-каналы

- Каналы извлекаются из фрагментов `#@name`, ссылок `t.me/...` и `tg://resolve?domain=...`; профили-указатели не публикуются.
- От одного канала — до 1000 профилей за окно.
- **Качество:** адаптивная модель по метрикам активности, доли поддерживаемых URI, статического фильтра, глубины анализа, уникальности и каденса. Порог 45 с надбавками; ускоренное одобрение сильного первого наблюдения; скидка за накопленные наблюдения; учёт момента роста; относительный порог по медиане пула каналов.
- **Статусы:** `candidate` → `approved` / `watch` / `excluded`; в `output/tg_channels.txt` попадают только `approved`, новые каналы добавляются в файл автоматически.
- **Переоценка:** старые каналы из реестра проверяются каждые `telegram.reevaluation_interval` запусков (по умолчанию 3) даже без упоминания в подписках; каналы, переставшие отвечать метрикам, удаляются из реестра и файла.
- **Приватность:** в состоянии каналов имена заменены SHA-256-хешами.

## Запуск

```bash
python -m subscription_collector                 # настройки из config.yaml
python -m subscription_collector --config path/to/config.yaml
```

Все параметры с русскими комментариями — в [config.yaml](config.yaml); флаги CLI лишь временно переопределяют YAML (`--strict-first-seen`, `--fail-on-empty`, лимиты источников, фильтра, доступности и скорости).

## Файлы

| Путь | Назначение |
|---|---|
| `config.yaml` | все настройки конвейера |
| `input.txt` | HTTPS-адреса подписок |
| `output/` | `vless.txt`, `trojan.txt`, `hysteria2.txt`, `tg_channels.txt` |
| `report.json` | обезличенный отчёт запуска |
| `.collector/state.json` | отпечатки профилей и даты наблюдений |
| `.collector/channel_state.json` | состояние качества каналов (хеши) |
| `.collector/tg_registry.txt` | реестр известных каналов |

## CI

Workflow каждые 4 часа запускает сборщик и коммитит изменившиеся `output/`, `report.json` и файлы `.collector/`. Ручной запуск — `workflow_dispatch`.

## Ограничения

Возраст URI достоверен только при наличии даты публикации (`Last-Modified` или время Telegram-поста). Статические проверки, TCP/TLS-проба и замер скорости подтверждают корректность, доступность и пропускную способность сервера, но не качество прокси-сервиса — итоговая проверка остаётся за пользователем в Android-клиенте.
