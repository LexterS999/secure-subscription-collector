# Secure Subscription Collector

Автоматический сборщик подписок для Android-клиентов, совместимых с URI-форматами **VLESS**, **Trojan** и **Hysteria2**. Проект получает подписки из `input.txt`, обнаруживает публичные Telegram-каналы в скачанных материалах, собирает профили из их свежих публикаций, исключает неподдерживаемые, неполные и низкокачественные конфигурации, удаляет дубликаты по правилам v2rayNG и публикует результат по протоколам. Итоговую работоспособность каждого профиля пользователь проверяет в своём Android-клиенте.

## Поддерживаемые протоколы

| Протокол | Требования статического фильтра |
|---|---|
| VLESS | UUID; TLS с SNI и fingerprint либо Reality с `encryption=none`, SNI, fingerprint и `pbk` |
| Trojan | Пароль, TLS, SNI и fingerprint |
| Hysteria2 / `hy2` | Пароль, TLS и SNI |

Все остальные схемы исключаются. Профили с `allowInsecure=1` или `insecure=1` не публикуются.

## Глубокий анализ профилей

После строгой проверки безопасности каждый профиль проходит глубокий анализ совместимости с Android-клиентами:

- значение `fp` должно быть одним из известных TLS-отпечатков (`chrome`, `firefox`, `safari`, `ios`, `android`, `edge`, `360`, `qq`, `random`, `randomized`);
- токены `alpn` ограничены набором `h2`, `http/1.1`, `h3`;
- путь WebSocket начинается с `/`; режимы gRPC ограничены `gun` и `multi`; режимы XHTTP — `auto`, `packet-up`, `stream-up`, `stream-one`;
- для Reality: `sid` — шестнадцатеричная строка до 16 символов, `spx` начинается с `/`, SNI является доменом;
- для Hysteria2: обфускация допускается только `salamander` и обязательно с `obfs-password`, параметр портов должен быть корректным перечислением диапазонов;
- для VLESS: `flow` допускается только `xtls-rprx-vision` и только вместе с TCP/TLS или Reality.

Профили, не прошедшие эти проверки, исключаются с конкретной обезличенной причиной.

## Публичные Telegram-превью

Если строка подписки ссылается на публичный канал (фрагмент вида `#@channel_name`, адрес `https://t.me/channel_name` или глубокая ссылка `tg://resolve?domain=channel_name`), сборщик извлекает имя канала и запрашивает только общедоступную страницу предпросмотра `https://t.me/s/<имя>`. Приватные ссылки, инвайты и сами профили-указатели не публикуются: такая строка служит только источником имени канала.

Из сообщений предпросмотра собираются только публикации за последние **72** часа (три суток) — параметр `telegram.max_post_age_hours`. Извлечённые URI всех поддерживаемых протоколов проходят тот же строгий фильтр, глубокий анализ и дедупликацию, что и профили из HTTPS-подписок, после чего публикуются вместе с ними; в отчёте они учитываются отдельно в разделе `telegram`.

Качество каждого канала оценивается адаптивной моделью по наблюдаемым метрикам: активности, доле поддерживаемых URI, результатам строгого фильтра и глубокого анализа, уникальности и частоте публикаций. Порог одобрения снижен до балла 55, а модель адаптивна: канал, чьё первое наблюдение превышает порог с надбавкой (65 при значениях по умолчанию), получает статус `approved` сразу; остальные новые каналы остаются в статусе `candidate` и подтверждаются вторым наблюдением. Каналы с низкой активностью или качеством переводятся в `watch` или `excluded` и могут вернуться в одобренные, когда их содержимое снова соответствует требованиям.

От одного канала за окно принимается не более 1000 профилей суммарно по всем протоколам — параметр `telegram.max_profiles_per_channel`.

В `output/tg_channels.txt` записываются только качественные каналы — те, что получили статус `approved` в текущем запуске. Полный список обнаруженных каналов хранится во внутреннем реестре `.collector/tg_registry.txt`. В файле состояния `.collector/channel_state.json` имена заменены SHA-256-хешем; хранятся только статус, балл, причина решения, число наблюдений и агрегированные результаты глубокого анализа без содержимого сообщений.

## Проверка доступности серверов

Перед публикацией каждый уникальный адрес сервера из профилей проходит TCP-проверку с предельным временем ожидания 1000 мс (`reachability.timeout_ms`). Соединение устанавливается параллельно: группы конечных точек обрабатываются батчами по 256 адресов при 56 одновременных воркерах (допустимый диапазон — от 50 до 60). Если системный DNS-резолвер не смог разрешить домен, выполняется один запасной запрос к сервису Google DNS-over-HTTPS (`https://dns.google/resolve`).

После установления TCP-соединения проба пытается получить подтверждение живости на прикладном уровне: сначала запрашивается эндпоинт Cloudflare trace (`/cdn-cgi/trace`), при отсутствии ответа — путь Google-проверки связности (`/generate_204`). Профили, чей сервер не ответил на TCP-соединение в течение 1000 мс, отбрасываются с причиной `unreachable_endpoint` и не попадают в итоговые файлы; ответившие серверы сохраняются.

Hysteria2 работает поверх QUIC/UDP, поэтому TCP-проба к таким серверам неприменима и не выполняется: их доступность пользователь проверяет в Android-клиенте.

## Накопительные файлы по протоколам

При успешной публикации команда автоматически создаёт каталог `output/`, если его ещё нет. В нём поддерживаются три файла с URI соответствующего протокола.

| Протокол | Файл |
|---|---|
| VLESS | `output/vless.txt` |
| Trojan | `output/trojan.txt` |
| Hysteria2, включая `hy2` | `output/hysteria2.txt` |

При каждом запуске сборщик атомарно заменяет каждый файл набором профилей соответствующего протокола, прошедших текущую обработку. Поэтому ранее опубликованный, но больше не поступающий профиль не остаётся в конечном файле, а остановка процесса не оставляет частично записанный файл. Пустые файлы для протоколов без профилей также создаются при первой публикации.

Каждый профиль сохраняется в совместимом URI-формате, а его имя после `#` заменяется коротким ASCII-фрагментом:

```text
TYPE-SECURITY-TRANSPORT-CODE
```

Примеры:

```text
VL-REALITY-GRPC-3ScvEG
TR-TLS-TCP-3ScvEG
HY2-TLS-UDP-3ScvEG
```

`CODE` — стабильный шестизначный буквенно-цифровой идентификатор. В имени нет IP/домена, SNI, UUID, пароля, ключа или исходного названия из сторонней подписки. Используются только буквы, цифры и дефисы, поэтому Android-клиенты отображают имя без URL-кодирования `%20` и специальных символов.

## Дедупликация в стиле v2rayNG

Дубликаты определяются так же, как в Android-приложении v2rayNG: профиль отождествляется со своей эффективной исходящей конфигурацией — протоколом, адресом, портом, учётными данными и всеми значимыми настройками транспорта и безопасности. Порядок query-параметров, исходное имя и посторонние параметры поставщика подписки на идентичность не влияют, а алиасы транспорта схлопываются: `ws` и `websocket`, `tcp` и `raw` обозначают одну конфигурацию.

Профили с одинаковыми сервером и портом, но разными SNI, Reality-ключами, TLS-параметрами, транспортом или другими соединительно значимыми полями сохраняются как отдельные конфигурации. Такое поведение соответствует ожиданиям пользователей v2rayNG и NekoBox.

## Настройка и запуск

Все постоянные параметры находятся в едином файле [`config.yaml`](config.yaml). Каждый параметр сопровождается русскоязычным комментарием: пути к входным и выходным файлам, лимиты загрузки источников, параллельность статического фильтра, окно публичных превью, модель качества каналов и политика публикации.

Укажите в `input.txt` публичные HTTPS-адреса подписок, по одному на строку, затем выполните:

```bash
python -m subscription_collector
```

Используйте другой файл настроек через `--config`:

```bash
python -m subscription_collector --config /path/to/config.yaml
```

Параметры командной строки остаются только временным переопределением значений из YAML. Флаги `--strict-first-seen` и `--no-strict-first-seen`, а также `--fail-on-empty` и `--no-fail-on-empty`, временно переопределяют одноимённые логические параметры раздела `behavior`. Параметр `strict_first_seen` ограничивает публикацию текущих кандидатов профилями, впервые замеченными в окне `sources.max_age_hours`. Параметр `fail_on_empty` возвращает код `2`, если текущий запуск не опубликовал ни одного профиля; файлы при этом содержат только текущий пустой набор, а не исторические результаты.

## Журнал выполнения и отчёт

Команда выводит русскоязычный журнал в стандартный вывод. Этапы охватывают подготовку, загрузку источников, статическую фильтрацию с глубоким анализом, удаление повторов, проверку доступности серверов и публикацию. Информационные сообщения `httpx` и `httpcore`, а также построчные данные об URI подавляются.

В журнал и `report.json` не попадают URI, домены, IP-адреса, SNI, ключи, учётные данные, исходные имена или содержимое ответов источников. После статической фильтрации журнал выводит только обезличенную сводку причин исключения, например `missing_sni: 42`. В отчёте сохраняются агрегированные причины исключения, свежесть источников, длительности этапов, безопасные количества новых и итоговых профилей по протоколам и сводка обработки Telegram-каналов.

## Файлы проекта

| Файл или каталог | Назначение |
|---|---|
| `config.yaml` | Единая постоянная конфигурация с русскоязычными пояснениями всех параметров |
| `input.txt` | Публичные HTTPS URL подписок: один адрес на строку |
| `output/` | Накопительные файлы `vless.txt`, `trojan.txt`, `hysteria2.txt` и список качественных каналов `tg_channels.txt` |
| `report.json` | Обезличенные итоги обработки и публикации |
| `.collector/state.json` | Отпечатки профилей и даты первого/последнего наблюдения без секретов |
| `.collector/channel_state.json` | Обезличенное состояние качества каналов: хеши вместо имён |
| `.collector/tg_registry.txt` | Внутренний реестр каналов текущего запуска |

## Автоматическое обновление

Обновление запускается вручную или по расписанию — каждые четыре часа. Workflow устанавливает Python-зависимости, выполняет сборщик, проверяет наличие файлов сохранённых Telegram-каналов (`output/tg_channels.txt` и `.collector/channel_state.json`) и публикует только изменившиеся `output/`, `report.json` и файлы состояния `.collector/state.json` и `.collector/channel_state.json`.

Изменение кода не запускает сбор подписок. Лимиты параллельности, размеры групп, тайм-ауты, окно публичных превью и политика публикации читаются из `config.yaml`.

## Ограничения

Возраст отдельного URI невозможно достоверно установить, если источник не передаёт дату публикации; при наличии HTTP `Last-Modified` применяется окно `sources.max_age_hours` из `config.yaml`, а для Telegram-публикаций — окно `telegram.max_post_age_hours` за последние трое суток. Статические проверки подтверждают корректность и совместимость профиля, но не его доступность из сети пользователя; итоговую проверку выполняет пользователь в своём Android-клиенте. Импорт и использование опубликованных профилей остаются под контролем пользователя.
